Apps · LoopLab

LoopLab.

Learn to code music — then DJ the club. A browser game that takes 9–13s from their first note to real Sonic Pi, and teaches them to find a bug by ear.

Children write code that makes a noise, and the noise tells them whether the code is right. That is the whole idea. LoopLab starts at play 60 and ends with a live set the child performs themselves — and the code they wrote to get there pastes straight into free Sonic Pi and runs.

It opens in a browser tab. No install, no admin ticket, no account. Names and stars stay on the device they were typed into.

How a session runs

Two halves, and the door between them is locked until the child has earned it.

The six Studio levels

Each one adds a single idea, and every keyword is the real Sonic Pi keyword — nothing has been simplified into a dialect the child then has to unlearn.

LevelWhat it addsCode
First NotesNotes are numbers. 60 is middle C, bigger sounds higher.play, sleep
Loop MagicRepeat music instead of writing it out again.3.times do … end
Drum MachineDrums, with their real sample names.sample :bd_haus
Super JamThe instrument changes everything.use_synth :saw
Two Loops at OnceParts running side by side, locked together.live_loop
Never the Same TwiceCode that composes — same program, different music.choose, rrand, use_bpm

The last one is worth a mention on its own. A child who writes play choose([60, 64, 67, 72]) and presses play twice hears two different tunes from one program. That is generative music, and eleven-year-olds get it in about four seconds.

It ends in the real thing

Every level hands back the code the child actually wrote, formatted to paste into Sonic Pi — free, on Mac, Windows, Linux and the Raspberry Pi — where it runs unchanged. That is the point of the whole game: LoopLab is the on-ramp, not the destination. A class can spend two lessons in the browser and arrive at Sonic Pi already knowing what live_loop does and why sleep matters.

If you want somewhere to take them next, the six-to-eight part Sonic Pi scheme of work in the library picks up roughly where LoopLab leaves off — synths and samples, threading loops, then deconstructing a real track.

A suggestion, not a mapping

Where it might sit in computing

LoopLab was built as a game, not as a scheme of work, so treat this as a nudge for your own planning rather than a coverage claim.

Upper KS2 (Years 5–6)

  • Designing, writing and debugging a program that accomplishes a specific goal — here the goal is audible, which is why children keep going.
  • Using sequence and repetition, and working with input and output.
  • Using logical reasoning to detect and correct errors. The Club is the closest thing I have found to genuine debugging at this age: the error is real, and the ear is the test.

KS3

  • Using two or more programming languages, at least one textual. Sonic Pi is Ruby, and by the final levels the child is typing it unaided.
  • Creating, reusing, revising and repurposing digital artefacts for a given audience — the audience being the dance floor.

Cross-curricular with music, it lands on tempo, pulse, layering and structure without anyone having to call it theory.

Running it in a room of thirty

The game is honest about the fact that it makes a noise. It asks for headphones before it will start — so you can hear your track, and so everyone else can hear theirs — and it carries a mute mode where the notes still fly across the screen, which is what you want when you are demonstrating on the board.

  • Up to 40 players per device, so a shared trolley or a lab machine works. A child taps their own name and carries on where they left off.
  • A short code moves progress between devices, for the child who is on a different laptop this week.
  • A finished-work summary records the stars, and whether the child used blocks or typed the code themselves — ready to paste into Google Classroom or drop in a folder.

Worth knowing before the lesson: progress is saved in the browser on that device. A locked-down browser that blocks site storage, or a nightly wipe of the machines, will take the stars with it — the game warns the child when it cannot save. Try it on one of your own school machines before you book the ICT suite.

What is on the device, and what is not

First name only, stored on the device, never sent anywhere. No accounts, no email, no class list to upload, nothing recorded. There is no server holding children's work because there is no server: the whole game is the page you have open.
